● The import test now passes, and so does the rest of the suite (20 tests).

  The rewrite is in the job, not the model. The CSV loop lives in
  app/Jobs/ProcessImportJob.php, so that's where I rewrote it. In
  app/Models/ImportJob.php I only added failed_rows and errors to $fillable and
  cast errors to an array.

  How the new loop works:
  - fgetcsv streams the file one row at a time, and blank lines are skipped.
  - Each row is validated: name is required, email must be a valid, unique
    email, and password is optional.
  - Each row is saved on its own with no shared transaction, so a bad row can't
    affect the others.
  - A failure is caught per row and appended to errors as {row, message}. row is
    the 1-based data row, so the duplicate in the test is row 2.
  - Progress (processed_rows, failed_rows, errors) is saved every 100 rows and
    again at the end. I chose every 100 to avoid a database write per row. Say
    so if you want it saved after every row.
  - At the end, total_rows is set and the status becomes completed_with_errors
    if any row failed, otherwise completed.
  - total_rows is only known once the file has been read, because the file is
    streamed and not counted in advance.

  Two changes you didn't ask for:
  - Test fix: the test's ProcessImportJob::dispatchSync() was silently doing
    nothing, because Queue::fake() swallows it. The job never ran, so the
    earlier failures didn't prove the bug the way I'd claimed. The test now
    builds the job, calls handle() directly, and calls failed() if it throws, as
    a queue worker would. The assertions are unchanged.
  - show response: ImportController::show now returns failed_rows and errors (an
    empty array when there are none). The test needed this to pass.

● I made three changes to app/Jobs/ProcessImportJob.php, and the full suite
  still passes (20 tests). I didn't add a test for any of them.

  - $tries = 1: a failed run is not retried.
  - WithoutOverlapping: the job's middleware() returns WithoutOverlapping keyed
    on the import's id, so only one worker processes a given import at a time. I
    added ->dontRelease(). With tries = 1, a released duplicate would count as
    an attempt and be marked failed, which would call failed() and overwrite the
    import's status. With dontRelease(), an overlapping duplicate is discarded.
  - Early return: handle() now starts with $this->importJob->refresh(), so the
    status is read fresh from the database. It returns immediately if the status
    is Completed or CompletedWithErrors, before anything is set to processing.

  A Failed import can still be re-run if it is dispatched again, since you only
  named the completed statuses. Say so if you want Failed treated as final too.
